# tsubame-fansite

[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)
[![Release](https://img.shields.io/github/v/release/robineverswift/tsubame-fansite)](https://github.com/robineverswift/tsubame-fansite/releases)

An **unofficial, non-commercial** fan-archive framework: a public works catalogue
plus a private owner console with a rights-holder window.

This project was originally built as **TSUBAME RECORD**, a fan archive of the
voice actress **Yuzuki Tsubame （柚木つばめ）**, recording her publicly listed
works. It is released, with identifying and personal material removed, so that
any fan can run the same kind of archive for their own artist. It is not
affiliated with the artist or any related organization.

**Live instance:** [yuzukitsubame.com](https://yuzukitsubame.com) — the original
TSUBAME RECORD, running this framework with the full catalogue.

## Use it for your own artist

The framework is configured through a single file, `subject.config.json`
(identity, palettes, fonts, brand assets), and fed by a replaceable data
adapter — DLsite ships as the reference adapter; other platforms plug in
behind the same contract. It is built for fans of individual creators:
voice actors, VTubers, and other independent artists.

- [docs/QUICKSTART.md](docs/QUICKSTART.md) — from fork to a deployed archive.
- [docs/ADAPTERS.md](docs/ADAPTERS.md) — the catalogue data contract.

## What is included

- **Public site** (Astro, JA / CN / EN UI modes): works archive with search,
  series grouping and an opt-in R18 gate; statistics computed from the data;
  an "on this day" layer; a channels directory; an About page written as a
  formal declaration.
- **Owner console** (`/admin`): X OAuth 2.0 (PKCE, read-only scopes) sign-in
  for the artist and the operator; a publication kill switch (reversible
  redirect); a message system with selectable reason paradigms and a standing
  reply; KV-backed records, milestones, drafts and feature flags.
- **Data pipeline**: a DLsite sync script and build scripts that regenerate
  the catalogue JSON, statistics and on-this-day data.

## Architecture

- **Static-first Astro site** deployed on Cloudflare Pages; no database and
  no server-side rendering for the public layer.
- **Cloudflare Pages Functions** under `functions/` serve the owner API
  (`/api/owner/*`) and guard `/admin`.
- **One KV namespace** (`PORTAL_STATE`) holds all mutable state: records,
  messages, drafts, milestones and feature flags.
- **Sign-in is X OAuth 2.0 with PKCE**, read-only scopes (`users.read`,
  `tweet.read`). Two identities are recognised: the artist (rights holder)
  and the operator. The artist can view, message, and pause or close the
  publication at any time via the kill switch.
- **Data is plain JSON** under `public/data/`, regenerated by the scripts in
  `scripts/`; the site never writes to the catalogue at runtime.

## Demo data

The demo dataset is **real but deliberately small**: the complete set of
**28 all-ages DLsite listings (2017–2026)** from the reference catalogue,
with statistics recomputed from exactly those works. Notes:

- No R18 listings are included. The R18 gate itself is in the code and types.
- The almanac/on-this-day data is generated from the release dates of the
  demo works (release anniversaries only). No personal or daily-life content
  is included anywhere in this repository.
- Cover images, avatars, brand artwork and audio are **placeholders** —
  replace them with your own assets.
- Message paradigms and the standing reply are **samples/templates**
  (marked サンプル / sample), not the live site's texts.

## What is not included

- The full catalogue, analytics reports, and all personal data.
- Real identifiers: operator/artist account IDs, e-mail addresses, domains
  and KV bindings are replaced by placeholders (`YOUR_X_USER_ID`,
  `example.com`, …). Search for `YOUR_` and `[アーティスト名]` to find the
  spots you must fill in.

## Setup

```sh
npm install
npm run dev
```

1. Copy `.env.example` to `.dev.vars` and fill in your own values.
2. Set `OWNER_X_USER_IDS` to the artist's X user ID(s), and replace
   `YOUR_X_USER_ID` in `functions/api/owner/me.js` and
   `functions/api/owner/message.js` with the operator's X user ID.
3. Bind a KV namespace as `PORTAL_STATE` in your Cloudflare Pages project.
4. Replace the demo data under `public/data/` with your own catalogue,
   and the `[アーティスト名]` placeholders with your artist's name.
